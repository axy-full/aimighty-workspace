# Screenplay PDF import and scene development

Studio → Script accepts PDF, TXT and Fountain. PDF.js 6.3.289 is pinned and loaded only when a PDF is chosen. Its worker, character maps, standard fonts and license are served from the same deployment. Reading uses local file bytes and a worker; PDF actions, attachments and scripts are never executed or fetched by this flow. No model request or credit charge is made by extraction.

The importer reads every page, preserves scene numbers and the complete extracted text, and requires review before replacing a current script. The uploaded original remains a protected workspace asset. SHA-256, page offsets, import time and acknowledged empty pages are saved with the private project. Publishing the script bible includes its original source; editor packages include the original as well. Existing scene nodes retain their old source bindings when a new screenplay replaces the editable script.

PDF limits are 20 MB, 400 pages, one million extracted characters and two minutes of worker execution. Oversized, encrypted and failed extractions do not import a partial result. Pages with little or no text require OCR or an explicit confirmation that they contain no screenplay text. **OCR is not implemented here.** Layout reconstruction uses PDF text coordinates. Complex columns, nonstandard scene headings and damaged font encodings require review against the original. Text extraction is not a guarantee of visual fidelity. Editing the text retires its original page mapping instead of attaching inaccurate page references to revisions.

The complete scene list is paginated. Select scenes explicitly for the canvas, with its remaining 250-node capacity shown. There is no former 60-scene slice. Admission rejects a whole batch if it does not fit, contains stale or duplicate source scenes, or exceeds the per-node text limit. It never shortens the scene. Scene intent and editable ordered beats are bound to a source change marker; outdated notes remain in the saved project but are excluded from new nodes until reviewed. Paragraph splitting is labeled as an editorial starting point, not AI analysis.

“Plan shot coverage” opens the existing Atomik quote and durable submission flow for one complete selected scene, with its source marker, page range and reviewed beats. Its request explicitly asks for dramatic beats, framing, lens, movement, lighting, palette, continuity and board directions. A request beyond the existing 12,000-character limit is refused without truncation or spending. The result is a proposed plan that the user can review and apply. No storyboard media is purchased by import or scene planning. Whole-screenplay AI analysis still needs a staged scene-processing workflow; the generic production-crew prompt has a bounded context window and does not read a full feature script in one pass.

Verification: synthetic 120-page Final Draft-style PDF exceeding the former 100 KB text limit; original bytes compared by SHA-256 after protected download; all 120 scenes, final-page marker, page ranges, beat edits and source-bound scene nodes persisted and recovered after reload. Scanned/empty-page warning and replacement refusal were checked at 360×640, 390×844, 844×390, 1440×900 and 1920×1080. Unit coverage includes page continuity, numbered suffixes, coordinate reconstruction, complete-source limits, stale/oversized batch refusal, beat/source publication and late-scene coverage requests. No paid calls were used.
