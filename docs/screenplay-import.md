# Screenplay PDF import and scene development

Studio → Script accepts PDF, TXT and Fountain. PDF.js 6.3.289 is pinned and loaded only when a PDF is chosen. Its worker, character maps, standard fonts and license are served from the same deployment. Reading uses local file bytes and a worker; PDF actions, attachments and scripts are never executed or fetched by this flow. No model request or credit charge is made by extraction.

The importer reads every page, preserves scene numbers and the complete extracted text, and requires review before replacing a current script. The uploaded original remains a protected workspace asset. SHA-256, page offsets, import time and acknowledged empty pages are saved with the private project. Publishing the script bible includes its original source; editor packages include the original as well. Existing scene nodes retain their old source bindings when a new screenplay replaces the editable script.

PDF limits are 20 MB, 400 pages, one million extracted characters and two minutes for the initial text pass. Oversized, encrypted and failed text extractions do not import a partial result. Pages with little or no text offer local English OCR or require explicit confirmation that they contain no screenplay text. The all-pages OCR option handles scans with printed headers or faulty embedded text. See the OCR workflow below. Layout reconstruction uses PDF text coordinates. Complex columns, nonstandard scene headings and damaged font encodings require review against the original. Text extraction is not a guarantee of visual fidelity. Editing the text retires its original page mapping instead of attaching inaccurate page references to revisions.

The complete scene list is paginated. Select scenes explicitly for the canvas, with its remaining 250-node capacity shown. There is no former 60-scene slice. Admission rejects a whole batch if it does not fit, contains stale or duplicate source scenes, or exceeds the per-node text limit. It never shortens the scene. Scene intent and editable ordered beats are bound to a source change marker; outdated notes remain in the saved project but are excluded from new nodes until reviewed. Paragraph splitting is labeled as an editorial starting point, not AI analysis.

“Plan shot coverage” opens the existing Atomik quote and durable submission flow for one complete selected scene, with its source marker, page range and reviewed beats. Its request explicitly asks for dramatic beats, framing, lens, movement, lighting, palette, continuity and board directions. A request beyond the existing 12,000-character limit is refused without truncation or spending. The result is a proposed plan that the user can review and apply. No storyboard media is purchased by import or scene planning. Whole-screenplay AI analysis still needs a staged scene-processing workflow; the generic production-crew prompt has a bounded context window and does not read a full feature script in one pass.

Verification: synthetic 120-page Final Draft-style PDF exceeding the former 100 KB text limit; original bytes compared by SHA-256 after protected download; all 120 scenes, final-page marker, page ranges, beat edits and source-bound scene nodes persisted and recovered after reload. Scanned/empty-page warning and replacement refusal were checked at 360×640, 390×844, 844×390, 1440×900 and 1920×1080. Unit coverage includes page continuity, numbered suffixes, coordinate reconstruction, complete-source limits, stale/oversized batch refusal, beat/source publication and late-scene coverage requests. No paid calls were used.

Primary references: [Mozilla PDF.js examples](https://mozilla.github.io/pdf.js/examples/) and [Document initialization and text extraction API](https://mozilla.github.io/pdf.js/api/draft/module-pdfjsLib.html). Package source and API types were also checked against the pinned installation on 14 September 2026.

## Local OCR and review

Tesseract.js 7.0.0, its 7.0.0 LSTM core and English language package 1.0.0 (`4.0.0_best_int`) are pinned. Installation copies the worker, scalar/SIMD/relaxed-SIMD cores, compressed language data, notices and a SHA-256 manifest into the deployment. No runtime CDN is used. Recognition happens in one native worker whose response policy permits same-origin scripts/data and WASM, disallows child workers, and does not enable general JavaScript evaluation. The Studio document keeps its existing production policy. A small adapter owns the pinned worker protocol so startup cancellation, worker errors and step timeouts can reject and terminate even before language initialization returns. A package upgrade requires adapter and real-browser requalification.

The original PDF is rendered locally, one OCR page at a time, onto a canvas bounded to four million pixels and a 3,072-pixel side. Recognition uses automatic skew correction and English LSTM text. This is not orientation repair for sideways scans, handwriting recognition, multilingual OCR, or a guarantee about arbitrary PDF decoder memory use. No customer text goes to a model provider; no generation credits are used. PDF rendering/worker operations have a one-minute step limit and an OCR session has a 30-minute ceiling. Device performance and image quality determine usable throughput; 400 pages is an admission ceiling, not a measured scanned-feature performance guarantee.

Each completed page replaces only that page's extracted text and recalculates all offsets without shortening the script. The original SHA-256 and file remain unchanged. Requested pages, engine/language, page confidence, manual-correction flags and explicit review acknowledgments are retained with the saved source. The API refuses duplicate, out-of-document, unprocessed or unreviewed OCR page records. Original bytes are uploaded through the existing scoped asset flow only after import is accepted.

Review shows one original page beside editable recognized text (stacked on mobile). Every recognized page requires its own acknowledgment; changing text clears that page's acknowledgment. Empty recognition still requires the separate original-is-blank confirmation. Confidence is an engine score, never advertised as an accuracy percentage. Cancellation or a failure preserves completed pages in the open panel; Resume OCR visits only unfinished pages. No partial import can be accepted while requested pages remain. Closing the panel/browser or changing productions discards this unimported local session; durable cross-device OCR sessions remain future work.

Verification on 15 September: real two-page scan-only PDF with original synthetic raster text, recognized using the actual WASM worker; original download hash and reviewed/corrected provenance recovered after saving/reload at all five viewports. A blocked language request proved immediate startup cancellation. An interrupted second recognition resumed without repeating or changing the completed first page. Existing 120-page text extraction and scene-node flows passed unchanged. Unit tests cover mixed-page offset preservation, source limits, confidence validation, complete review admission, initialization failure, cancellation and step timeout. This is not a qualification against a corpus of degraded commercial scans.
