Public repository research performed no authorization grant, app registration, or paid operation; the later owner-approved live connection is recorded below. ## Current Cloud API integration

The authoritative model reference documents `POST https://api.higgsfield.ai/marketing-studio/image` with `Authorization: Key KEY_ID:KEY_SECRET`. Direct generation/editing uses prompt, images and output settings. Enhanced generation additionally requires a visible preset and exactly one product image, optionally followed by one model image. The second image has an assigned role; sending several product views as product-plus-model is incorrect. Without a second image, enhancement remains product-only.

Discover presets through `GET /marketing-studio/image/presets?size=50`, following its returned cursor with the same credentials. Never invent or hardcode preset IDs. Supported resolutions are 1k/2k/4k and aspects are auto, 1:1, 3:2, 2:3, 4:3, 3:4, 16:9, 9:16 and 21:9. Enhancement has an additional charge, so the app uses a live estimate instead of copying promotional list prices. [Model-specific API reference](https://console.higgsfield.ai/models/marketing-studio%2Fimage/api-reference).

The repo implements this in `lib/higgsfieldMarketing.ts` and the existing Higgsfield engine. It uses `POST /estimate/marketing-studio/image`, validates the preset under the credential fingerprint, resolves authorized original images, and retains the accepted provider request for recovery. Its image preset catalogue is not the consumer video/template catalogue.

Higgsfield instructs integrators to prefer model-specific Console documentation over supplementary OpenAPI. Absence from OpenAPI alone does not establish unavailability. This review found no authoritative Cloud API contract for consumer products, avatars, brand kits, DTC Ads Engine, or template-based Marketing Video; no guessed endpoint should be submitted with `HF_CREDENTIALS`. [Official source-priority guidance](https://docs.higgsfield.ai/docs/llms.txt).

## Consumer workflow contracts

The official CLI exposes model and workflow discovery separately. Read the live schema before selecting a consumer job type; a model name is not a Cloud REST path. `marketing_studio_video` accepts a prompt, product/website-product IDs, avatar selections, optional reference media, and video settings. Product IDs and website-product IDs are mutually exclusive, as are an ad reference and hook/setting IDs. Its documented defaults include 15 seconds, 720p and UGC mode. Public documentation disagrees on 1080p availability and duration bounds, so a future connection must use the authenticated live schema rather than a fixed copied enum. [Official CLI model catalogue](https://github.com/higgsfield-ai/cli/blob/main/MODELS.md).

The official marketing workflow supports nine prompt-based modes. Hooks/settings are only valid for the UGC, tutorial, unboxing, review and UGC try-on modes. Curated or custom avatars can be selected; when no specific person is selected, some UGC modes can synthesize a presenter. This differs from Cloud image enhancement, which does not invent a person when the model image is omitted. [Marketing workflow](https://github.com/higgsfield-ai/skills/blob/main/higgsfield-generate/SKILL.md), [mode restrictions](https://github.com/higgsfield-ai/skills/blob/main/higgsfield-generate/references/marketing-modes.md).

## Read-only verified OAuth discovery

`GET https://mcp.higgsfield.ai/.well-known/oauth-protected-resource` advertises resource `https://mcp.higgsfield.ai/mcp`, bearer-header access, and scopes `openid email offline_access`. It points redirect-capable clients to `https://clerk.higgsfield.ai`, and separately advertises a device-flow service. [Live resource discovery](https://mcp.higgsfield.ai/.well-known/oauth-protected-resource).

An unauthenticated TLS-verified GET of `https://clerk.higgsfield.ai/.well-known/oauth-authorization-server` succeeded. The response advertises `/oauth/authorize`, `/oauth/token`, `/oauth/token/revoke`, `/oauth/register`, `/oauth/device_authorization`, S256 PKCE, authorization-code/refresh-token/device-code grants, public-client authentication (`none`), and Client ID Metadata Documents. The alternate device service's standard `/.well-known/oauth-authorization-server` returned 404. No claim is made about its undocumented endpoint layout. No registration or authorization request was sent. [Authorization metadata](https://clerk.higgsfield.ai/.well-known/oauth-authorization-server), [Clerk OAuth guidance](https://clerk.com/docs/guides/configure/auth-strategies/oauth/scoped-access).

The connector now implements a distinct owner-authorized OAuth connection: fixed trusted issuer/resource; an app-owned HTTPS Client ID Metadata Document and callback; one-use, expiring state bound to the exact browser session, user and workspace; S256 PKCE; encrypted tokens with refresh rotation; and local disconnect with best-effort revocation. A legitimate pre-registered client ID can be configured with `HF_CONSUMER_CLIENT_ID`; the shared CLI client ID is never reused. Production's `APP_ORIGIN` must be the canonical HTTPS origin. Tokens are server-only and never returned to the UI.

After consent, the owner can perform bounded MCP initialization and `tools/list` discovery. This does not execute tools, upload media, generate, score or select a billing workspace. Lexical matches in the diagnostics are discovery hints, not verified feature support. Before adding paid execution, verify the authenticated tool schemas and billing workspace, allowlist specific operations, obtain authoritative quotes, retain accepted job IDs, and prevent ambiguous mutations from being retried.

The SDK also documents a development-preview Cloud Agent session API. Its generic message interface does not establish deterministic Marketing Video or Virality tools, per-operation quoting, spending limits, or account enablement. It is not used as an unfenced alternative to typed workflows. [SDK source](https://github.com/higgsfield-ai/higgsfield-client-js/tree/e3f274249962417e21f6566d4eecec6d8491d11c).

## Implemented release — 18 September 2026

### Authenticated catalogue qualification

The workspace owner explicitly authorized Particl's own OAuth client, and the live callback and encrypted connection succeeded. An owner-triggered `tools/list` returned 98 tools. The catalogue includes `generate_video`, `marketing_studio_v2_presets`, `marketing_studio_v2_costs`, `marketing_studio_v2_create`, `marketing_studio_v2_status` and `virality_predictor`. It does not advertise the CLI's ad-reference or brand-kit entity operations. Generic model prompts referring to a missing tool are not proof that the missing tool is callable.

The live `generate_video` definition documents `get_cost:true` as a non-submitting credit preflight, and advertises `marketing_studio_video` plus the direct reference-video models `hf_mult_replace_object` and `hf_mult_motion_control`. The latter are a possible supported path to source-ad product replacement or motion matching, distinct from the CLI ad-reference entity workflow. Their constraints still require model-catalog qualification.

`select_workspace` explicitly changes a selection that persists across sessions and clients. No documented request-scoped MCP workspace binding has been found. A local lock alone cannot prove isolation from other clients changing that selection. Paid integration must address wallet binding rather than silently selecting a workspace.

The owner can now run a fixed, bounded qualification set: workspace listing, selected model constraints, v2 preset examples and prices, the ad-multiplier workflow text, and a hardcoded `get_cost:true` product-video quote. No user-supplied tool names/arguments, workspace switch, media upload, paid generation, or scoring call is admitted. Provider instructions and suggested recovery tools are returned as inert diagnostic text, never executed.

### Live account observations and controlled verification

The production owner completed all nine read-only qualification calls. The account returned 986 Marketing Studio v2 presets and a versioned pricing document. `marketing_studio_video` advertised 12–15 seconds, 480p/720p/1080p and seven aspect options. A 15-second, 720p, 16:9 product demonstration returned `{cost:{credits:75,credits_exact:75}}`; this was a cost-only request and submitted no job. The provider defaulted audio on, so the verification payload now sets that choice explicitly. Quotes are account observations at that moment, not a fixed retail rate or USD conversion.

Typed text-to-Marketing-Video admission uses an immutable saved quote, exact owner OAuth generation, observed Higgsfield wallet, sufficient balance and a fresh matching price. The sole paid request happens after a durable database claim. A timeout or unsupported acknowledgement stays uncertain and cannot be retried automatically; accepted UUIDs remain recoverable after a source draft is removed. The owner verification panel uses a separate synthetic-product project and requires explicit approval of the displayed wallet and credit total.

The bounded job list pins admitted unfinished jobs ahead of recent quotes. A browser attempt omitted from recent history continues to block a new submission until the user reads that exact saved record. Only an authoritative terminal/admitted state or a server-confirmed expired, undispatched quote clears that attempt guard; browser time alone cannot establish safe recovery.

An owner-approved 75-credit rehearsal was submitted once on 18 September. Higgsfield returned `{results:[{id,model:"marketing_studio_video",type:"video",status:"pending",params}]}` with the requested settings. The initial parser preserved this unknown shape as an uncertain receipt; the qualified parser now accepts exactly one matching video result. Recovery compares the immutable saved receipt, scopes it to the original owner and connection, and adopts that existing UUID without another generation request. The diagnostic response can be truncated without losing a separately saved, validated acknowledgement ID; conflicting IDs remain uncertain. Output collection is not established by a pending acknowledgement.

Higgsfield's selected workspace is global across its MCP/CLI clients. Checking it immediately before submission detects prior changes but cannot atomically prevent another client switching it afterwards. No documented per-request workspace binding was found, and Particl does not invent a header or claim that guarantee. This consumer pathway is owner-operated; it is not qualified for unattended multi-tenant spending.

Native reference-ad analysis uses twelve timestamped stills from an uploaded or generated video of up to sixty seconds, with the existing reviewed Atomik model, effort, quote and recovery flow. The saved analysis records frame evidence and the canonical original identity. It proposes editable beats, framing, camera direction, pacing, colour and uncertainties; applying it requires explicit review and the same selected original. It does not claim to hear audio or observe motion between sampled frames. Compatible video variants bind that original to a graph source and require separate generation review. Save, deletion checks and delivery retain current and historical reference videos. This is a native analysis workflow, distinct from Higgsfield's unavailable `ad_reference` entity API.

### Completed provider result and original retention

Status-only recovery of the original rehearsal returned `{raw_data:{id,status:"completed",job_set_type:"marketing_studio_video",result_url,params}}`. Only that exact job/model envelope and the submitted prompt, duration, resolution, aspect, audio and creative mode qualify its HTTPS `result_url` for collection. Unknown envelopes remain diagnostic; thumbnails, alternative encodings and nested guessed URLs are never treated as the original.

The downloaded rehearsal contains 5,893,035 bytes: 1280×720 AVC video lasting approximately 15.04 seconds and stereo 44.1 kHz AAC audio lasting approximately 15.07 seconds. Browser playback completed without a media error. Provider parameter metadata claimed different dimensions, so stored dimensions come from the actual MP4. Its SHA-256 is `31c90ef59150720a55f4ec70bdc9a06c44025ea9661c128f79a08e7fcf521e5b`.

The creative constraint did not pass: despite the submitted no-people prompt, the provider's default `ugc` enhancement introduced a presenter and testimonial claims. No replacement was submitted. Native Marketing Video therefore exposes the nine documented creative modes and defaults new inputs to Product showcase. Legacy jobs retain their omitted mode and are labelled with the provider's UGC default. A different format cannot use another format's quote, and input edits clear wallet approval. This does not guarantee creative compliance; outputs still require review. [Documented creative modes](https://github.com/higgsfield-ai/skills/blob/d071406147a37b835bed09543d85ab3e9bd85c7d/higgsfield-generate/references/marketing-modes.md).

Original retention uses a bounded DNS-pinned HTTPS fetch, actual MP4 validation, private storage, an immutable digest and a durable quota reservation. Its deterministic generation ID and retained receipt recover an interrupted completion without submitting another job or duplicating the asset. Workspace deletion and backup guards preserve ambiguous writes. The native panel can add only the verified stored original to the same project. Usage separates approved Higgsfield-credit quotes from Particl credits and USD; it does not claim an invoice, live balance or a refund. Production collection is verified separately from the successful provider download.

### Remaining provider boundaries

Authenticated `models_explore get` returned `Model not found` for both `brain_activity` and `virality_predictor`, although discovery advertises a `virality_predictor` create/preview tool. That tool has no documented non-submitting price parameter. The official CLI documents a generic `generate cost` command, but its repository contains no underlying HTTP implementation or machine-readable virality price/report contract. Paid scoring stays disabled until those contracts can be verified; no sample score is presented as a real result.

Browser checks use isolated fixtures and establish application wiring and recovery behavior, not load certification or full Higgsfield parity. Consumer brand/product/avatar entity services, automatic provider ad-reference analysis, social publishing and complete v2 website-template execution remain unavailable or unqualified. Native brand extraction and reference analysis are separate implementations with the limits above.
