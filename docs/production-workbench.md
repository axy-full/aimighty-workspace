# Particl production workbench

The September 13 redesign is integrated selectively over current main. The source archive’s application baseline was not substituted for the newer backend. The original Particl logo, neutral palette, desktop stages/canvas/inspector and mobile bottom navigation are retained. `/` redirects to `/workbench`; existing production and review routes remain available.

## Studio, Gen and workspace

Studio, Gen and Workspace are first-class sections in the shared navigation. `/generate?mode=video|images|audio` opens the dedicated creation desk and searchable take browser. Existing `/make/video`, `/make/images` and `/make/audio` links open the same redesigned interface and retain reference parameters. Drafts and interrupted paid requests remain scoped to the signed-in person, workspace and generation mode. Reusing a take loads its prompt for editing and an explicit priced submission; it does not start a paid job directly.

Workspace/account settings, team, credits/plan and usage share the studio's monochrome management design. Their existing endpoints, roles and prices are unchanged. Workspace switching and sign-out clear private browser caches only after the server accepts the change. Leaving the production workbench through the section navigation or workspace menu drains pending saves first. Stripe remains deferred and checkout continues to fail closed when unconfigured.

Atomik uses the original eight-dot ring in `components/AtomikMark.tsx`, matching the previous website's `design/particl-v2/assets/atomik-ring-on-dark.svg`. The prototype's orbital atom illustration is removed. The original Particl trail and branded wordmark remain intact.

## Connected workflow

A signed-in user can create or open a production in a private working space, write a brief/script, break it into editable nodes, bind character/world/moodboard references, generate a priced take, inspect recovered versions, save deterministic image operations, assemble a sequence and download an encoded movie or EDL/source package. Node bindings and exported manifests retain reference and take lineage. The sample campaign is editable reference material; signed-out visitors must sign in to save, upload or run paid jobs.

`workbench_projects` stores owner-scoped snapshots with compare-and-swap revisions. `workbench_shots` maps each owner/draft/node to an existing production shot. Real production IDs are server-owned and cannot be swapped through an update. `workbench_bibles` stores immutable published context versions; collaborators create their own drafts from shared context. Database clients and media access run within the established tenant context.

Workbench requests carry the account/workspace scope captured by the server-rendered document. Project writes require that scope and reject stale or missing context before reading the private payload or changing storage; project reads reject a supplied stale scope. The same captured scope accompanies generation recovery and workbench uploads. Switching accounts in another tab cannot save an outgoing draft or submit its paid request under the new session. A server-rendered scope change remounts the studio instead of retaining the previous account's in-memory draft.

The shared application layout also captures this scope for Gen, Library, asset creation, Ideas, Cast and Theatre uploads. Browser upload, chunk, finish and cancellation calls require it; explicit API-token callers retain their authenticated integration path. Uploads never fetch a fresh account scope immediately before sending a selected file. A server-rendered account change remounts private application state, and cast creation after an upload checks the original captured scope too.

Browser uploads retain the original chunk session, file metadata and a fingerprint of every source byte in scoped local storage. File bytes are never persisted there; fingerprinting reads bounded 3.5 MB slices. The Uploads panel can recover a lost successful finish response after reload, resume server-prepared bytes without reselecting the file, or accept the exact original file to resend only missing chunks. Small files use the same recoverable protocol. Cancellation is explicit and server-confirmed. Recovery remains subject to the server's 24-hour upload expiry; an expired or removed session requires checking the reference library and explicitly dismissing the old request before a new upload. Restored uploads remain in the reference library; a reload does not automatically bind them to a previously open node or private form.

Publishing includes each selected asset's transitive references and parent versions, plus sources used by saved node versions and linked nodes. Missing bindings and cyclic asset lineage stop publication before a shared version is written. A publication names the shared version the author reviewed; concurrent publications from that same base accept one winner. The other author keeps their private draft and can download it or save before loading the latest shared context. Refreshing never republishes automatically; changes require another explicit publish.

Draft and publication writes verify referenced upload and generation records inside the database write transaction. Media deletion uses the same transaction boundary and checks private drafts, shared versions and mapped take history. A saved reference prevents deletion; an earlier deletion prevents a stale draft from restoring that reference. Shared publication history keeps its original sources. Replacing a workspace database initializes the workbench schema on the new database client.

`/api/workbench/engines` exposes only configured media models and credit estimates. Generate binds references to existing upload/generation records, disables implicit prompt refinement, maps to a real shot, and submits `/api/generate`. Jobs run using the existing provider adapters, native worker/Inngest/inline execution (docs/native-dispatch.md), storage and meter. Activity independently recovers media jobs and Atomik plans, including older active jobs; completion does not overwrite a newer manual selection.

Genie and the director, DOP, editor, production designer, costume stylist, producer and continuity supervisor run one selected task at a time. `/api/workbench/atomik` saves an addressable job, quotes a bounded output budget, reserves spend and runs asynchronously. Auto selects an economical priced language model from the configured Gateway catalogue. Users explicitly confirm the quoted run and can edit applied plan nodes individually.

Paid media and Atomik submissions persist retry identities before submission and reuse exact payloads after an interrupted response. Server claims are durable and tenant/user scoped. Shared atomic reservations include outstanding work in credit, concurrency, project and token limits. Delayed worker delivery cannot repeat an inline paid call. An ambiguous provider result is never automatically resubmitted. Video submission claims cover transport failures and delayed releases; known handles recover after lost database acknowledgments, while uncertain outcomes retain their estimated spend. A complete database outage before a returned handle can be saved requires support to reconcile that task ID.

Image tiles use authenticated, cached 640-pixel WebP previews with original-image fallback; video tiles reuse the existing bounded poster capture/cache. Uploads use the existing bounded chunk client and server-side streaming assembly. Saved image transforms create new uploads and preserve their source lineage. The legacy workbench upload endpoint delegates to the existing authenticated upload handler.

## Export and context limits

- Atomik reads project text, uploaded plain text up to 100 KB per file, actual selected image pixels and browser-decoded video frames. Vision-capable models receive bounded 512-pixel JPEGs: at most three frames per video, sampled at 10%, 50% and 90%, with six visuals total. References must resolve to authorized workspace uploads, generations or bundled samples; originals remain unchanged and quoted requests retain the exact reference payload. PDF/audio references and saved links remain metadata only; arbitrary websites are not fetched. Live model quality has not been tested with paid calls.
- Image crop, grade, transform, mask and mix operations are deterministic. Saved image edits become source assets; video edits beyond sequence trim/framing still require an external editor.
- EDL supports one video track, straight cuts, integer 24/25/30 fps and zero-based source timecode. Scratch audio travels separately. Source frame rates and embedded timecodes are not probed. Validate relinking in the target editor before delivery.
- Final movie export opens the exact `/workbench/movie` route with a schema-validated, ten-minute session snapshot tied to the server-derived workspace and user. The renderer checks the current account again before media loading. That route alone permits the bundled WebAssembly worker; other app policies are unchanged. Encoding runs on this device with native WebCodecs through lazy-loaded Mediabunny 1.56.2. MP4 uses native H.264 and locally rebuilt `@mediabunny/aac-encoder` 1.56.2-particl.1; `movie-aac.ts` compensates its 1024-sample FFmpeg priming frame with negative packet timestamps and trims end padding. Native AAC is avoided because platform encoders do not reliably expose priming. The AAC pulse-alignment regression must pass before a version upgrade; WebM uses VP9 (or VP8) and Opus. It encodes exact 24/25/30 fps timeline frames, source trims and image holds into 720p/1080p SDR output, with aspect fit or crop. Clip audio follows the trim; the selected soundtrack starts at zero, is cut at sequence end and is silent after its own end. Sources mix at 48 kHz stereo; the entire mix is reduced when necessary to prevent clipping. There is no separate track gain automation.
- Movie limits are 3 minutes, 200 MB total source media, 200 MB output and 40 megapixel inputs. Rendering requires supported native decoders/encoders and enough device memory; the page must remain open. Unsupported formats, missing files and trims beyond source duration stop the render explicitly. Media stays in the browser after authenticated same-origin fetches; rendering does not upload media or consume generation credits. The downloadable result is temporary until saved to disk. Transitions, HDR/colour-managed masters and fractional/drop-frame rates are not supported. The library licenses, corresponding source kit, reproducible build/relink recipe and artifact checksums are linked at `/licenses/mediabunny.txt`.
- Source ZIPs include actual source bytes and recursive reference lineage, with a 200 MB browser limit. Larger deliveries require the EDL and separately collected sources. The EDL keeps audio separate and requires target-editor conform validation.
- An unresolved paid submission remains recoverable and does not start a replacement job automatically.
- In `/workbench`, conflicting edits from another window stop autosave rather than silently overwrite.
- The Suites and `/workspace` editors of one draft (Rig, the Studio stages, Edit & Sound, Marketing) each keep the draft as the server last held it. When another save lands first (409 `revision_conflict`), the edits made since then are merged into the newer version (`lib/workbench/merge.ts`: key by key, lists of records by id, a record one side deleted and the other changed is kept, a move only one side made is kept) and saved at its revision; nothing either side added or changed is dropped and no id appears twice. A save whose reply was lost is reconciled the same way, which cannot apply anything twice. After repeated conflicts the editor stops and says so (the Rig reloads), as before.
- Production provider execution is connected but release verification uses mocks only; no paid provider call is authorized by the release test plan.

## Verification

Run `npm run lint`, `npx tsc --noEmit`, `npm run test:unit` and `npm run build`. Run the dedicated workbench suite with a local `ENGINE_MOCK=1` development server and `PW_BASE_URL=http://localhost:4551 PW_CHANNEL=chrome npx playwright test --config=playwright.workbench.config.ts`. It exercises real local authentication and mocked jobs at 360×640, 390×844, 844×390, 1440×900 and 1920×1080. The mock-server guard prevents this workflow suite from calling a production provider. `tests/movie-export.spec.ts` also synthesizes video/stills/audio locally, downloads the real encoded result, decodes all frames and checks exact cut boundaries, source in-points, aspect framing and frequency-specific synchronized audio. Desktop coverage includes MP4 when available, exact AAC duration and a pulse aligned within 3 ms, muted output, cancellation, invalid source trims and stale-account snapshot rejection. General script eval is disabled before encoder worker creation in development-browser coverage; the production export policy has no general eval allowance.

Unit coverage includes tenant/owner isolation, concurrent snapshot updates, stable shot mapping, immutable bible publication, media sharing, duplicate paid submits, spend reservation races, delayed worker fallback, stale Atomik recovery, context boundaries, job recovery and exact-frame EDL/source packaging. Deployment uses the existing `particlstudio` Vercel project and preserves remote environment settings.
# Durable pipeline extension

Studio links to a separate Pipelines page using the current production ID. Pipelines consume only an explicitly published immutable context version, keep runs private to their creator, and require a fresh exact batch quote and approval for each ready generation stage. Image/video/audio outputs use the shared durable admission path. A selected timeline is handed to the existing movie renderer; it is labelled as an editorial timeline until encoded. See [durable-production-pipelines.md](durable-production-pipelines.md) for schema, ownership, recovery, and limits.
