# §19 step 2 — §1 confirmed against the code

Read-only audit of branch feat/v2m-7-settings (the full v2 stack), 11 September 2026. 119 API routes and the foundation modules were read by fourteen independent readers; every claimed bypass or tenancy gap below survived two further independent refuters, and 14 refuted claims were dropped. ## 1. Keys

Every secret is an environment variable on the deployment, or a sealed row in the platform record. Nothing is in the client bundle (tests/unit/bundle.spec.ts greps built chunks for vendor literals, lib/vendorRates.ts:18-19).

**Vendor keys (five names, one env each).** `VendorKeyName = ark | gemini | gateway | fal | elevenlabs` → `ARK_API_KEY`, `GEMINI_API_KEY`, `AI_GATEWAY_API_KEY`, `FAL_KEY`, `ELEVENLABS_API_KEY` (lib/vendorKeys.ts:13-18). Resolution order in `vendorKey(name)` (lib/vendorKeys.ts:28-36): the workspace's own sealed key (`ws.keys[name]`) → the deployment env only when `ws.usesPlatformKeys` → `null` (an own-keys workspace with no key for that vendor is unrouted). With no tenant in scope it falls straight to env (lib/vendorKeys.ts:35). Gateway auth adds a third door: Vercel OIDC when `deploymentIdentityAllowed()` (lib/gateway.ts:27-45; lib/vendorKeys.ts:49-52 = `!ws || ws.usesPlatformKeys`).

**Per-workspace sealed keys.** `workspaces.keys_enc` is one JSON object sealed AES-256-GCM under sha256(`KEYRING_SECRET`) (lib/keyring.ts:13-42; required in production, dev fallback `particl-dev-keyring` lib/keyring.ts:15-20); opened on every `rowToWorkspace` (lib/platform.ts:237). Written by PUT/DELETE /api/workspaces/keys (requireOwner, app/api/workspaces/keys/route.ts:25-74 → `setWorkspaceKeys` lib/platform.ts:675-682) and, at workspace creation, by the platform-minted Vercel AI Gateway key stored as `{gateway: …}` plus `gateway_key_id` when `VERCEL_TOKEN`+`VERCEL_TEAM_ID` are set (lib/platform.ts:534-544; lib/vercelKeys.ts:21-46, spendAttribution `team` :37). Only the last four characters are ever returned (app/api/workspaces/keys/route.ts:42; lib/keyring.ts:45-48). Legacy workspace (`ws_legacy`): env keys only, keys always `{}` (lib/platform.ts:244-248).

**Tenant database credentials.** `workspaces.db_url` + `db_token_enc` (same keyring seal, lib/platform.ts:239,520); minted by Turso Platform API with `expiration=never&authorization=full-access` (lib/provision.ts:21-50; needs `TURSO_API_TOKEN`, `TURSO_ORG`, optional `TURSO_GROUP`, `TURSO_API_URL`); local dev `file:.data/ws_<slug>.db` (lib/provision.ts:26). Legacy DB is `TURSO_DATABASE_URL`/`TURSO_AUTH_TOKEN` read at request time (lib/platform.ts:244-247; lib/auth.ts:380-382).

**Platform record.** `PLATFORM_DATABASE_URL` / `PLATFORM_AUTH_TOKEN`, falling back to `TURSO_*` then `file:.data/ark.db` (lib/platform.ts:29-37).

**Prompt writer (not routed through vendorKey).** `ANTHROPIC_API_KEY` / `ANTHROPIC_AUTH_TOKEN` are read straight from env by the Anthropic SDK (lib/enhance.ts:75, :324-331) and select the direct-Anthropic writer for every workspace regardless of its own keys (lib/enhance.ts:125-128); `REFINE_PROVIDER`, `ANTHROPIC_PROMPT_MODEL`, `GATEWAY_PROMPT_MODELS`, `ARK_TEXT_MODEL`, `ARK_BASE_URL` (lib/enhance.ts:37-84).

**Other secrets.** `BLOB_READ_WRITE_TOKEN` (single deployment-wide Blob token, lib/storage.ts:55-57); `SESSION_SECRET` (IP-hash salt, falls back to `TURSO_AUTH_TOKEN` then literal `"particl"`, lib/auth.ts:457; app/api/access-request/route.ts:35); `CRON_SECRET` (app/api/cron/sync/route.ts:39-45); `INNGEST_SIGNING_KEY`+`INNGEST_EVENT_KEY` (lib/inngest.ts:44-47); `VAPID_PRIVATE_KEY`, `NEXT_PUBLIC_VAPID_PUBLIC_KEY`, `VAPID_SUBJECT` (lib/push.ts:16,86-90); `RESEND_API_KEY`, `MAIL_FROM` (lib/mail.ts:21-33); `SUPER_ADMIN_EMAIL` default `axy@akshaypanchal.com` (lib/platform.ts:39-41); `ENGINE_MOCK=1` in gitignored `.env.local` only (lib/mock.ts:17). Stripe/Razorpay: absent — `startCheckout` throws "not wired" (lib/payments.ts:14-25). `FAL_KEY`: absent from `.env.local` and `.env.example` (docs/particl-sow.md:27); production value unverifiable read-only.

**Who pays is decided by key presence, not by a billing flag.** `paidByPlatform(name) = !ws.legacy && ws.usesPlatformKeys && !ws.keys[name]` (lib/platformSpend.ts:20-24); `vendorKeyNameFor(provider)` maps byteplus→ark, google→gemini|gateway, vercel→gateway, fal→fal, elevenlabs→elevenlabs, with no Anthropic case (default `ark`) (lib/platformSpend.ts:62-70). Consequence (confirmed): the platform-minted gateway key stored in `keys_enc.gateway` makes Atomik text and gateway stills look like the workspace's own money (billed 0 credits, excluded from the allowance, lib/meter.ts:55-57, lib/platformSpend.ts:49) while the bill lands on the platform's Vercel team.

## 3. Metering layer

**Exists: one function.** `meter(e: MeterEvent, opts: { critical?: boolean })` at lib/meter.ts:51. `MeterEvent = { id, kind: video|image|audio|training|text, engine, model, status: running|succeeded|failed, engineCostUsd?, projectId?, shotId?, durationMs?, createdBy?, workspaceId? }` (lib/meter.ts:27-42). Upserts one row per job id into **platform** `meter_events` (DDL lib/platform.ts:137-154: id, workspace_id, project_id, shot_id, kind, engine, model, status, engine_cost_usd, billed_credits, paid_by_platform, duration_ms, created_by, created_at, updated_at) via `ON CONFLICT(id) DO UPDATE` (lib/meter.ts:64-77). `critical` defaults to `status === "running"` and throws after two failed writes so unbillable work does not start (lib/meter.ts:52,60-87). It returns silently when no workspace is in scope (lib/meter.ts:53-54) — latent, every current caller is inside withTenant/runInTenant.

**billedCredits today.** `billed = cost == null ? null : paidByPlatform(vendorKeyNameFor(engine)) ? billCredits(cost, marginKeyOf(kind, model)) : 0` (lib/meter.ts:55-57). `billCreditsWith(usd, margin, perCredit) = usd > 0 ? max(1, ceil(usd × margin / perCredit − 1e-9)) : 0` (lib/creditTerms.ts:82-85); `perCredit = CREDIT_USD` default 0.10 (lib/creditTerms.ts:38-41). **Multiplier: `LAUNCH_MARGIN = 1.5`, `DEFAULT_MARGINS = {"*": 1.5}`** (lib/creditTerms.ts:52-55), env `CREDIT_MARGINS` JSON override cached for the process lifetime (lib/creditTerms.ts:57-66); `marginFor(key, table)` (lib/creditTerms.ts:76-79) is keyed by **model id** for video/image and by class string `identity-training` / `elevenlabs` / `text` otherwise (lib/creditTerms.ts:69-74) — `CREDIT_MARGINS={"fal":1.7}` would do nothing. The same rounding is re-implemented in SQL (lib/creditSql.ts:9-31) for caps/usage and in the browser (lib/rateTable.ts:151-156) with margin pre-multiplied server-side (lib/rateTable.server.ts:20-28).

**Balance and spent are derived, never written.** balance = SUM(credit_grants.credits) − SUM(meter_events.billed_credits WHERE paid_by_platform=1) (lib/credits.ts:27-31; lib/platform.ts:639-643; lib/meter.ts:91-98). Project/production `spent` is recomputed from tenant `generations.cost_usd + refine_cost_usd` (lib/caps.ts:49-66; lib/productions.ts:59-73) — a second ledger with workspace-level `creditsApply` and no per-vendor `paid_by_platform` notion (**confirmed divergence** for a platform-keys workspace holding one own vendor key: lib/caps.ts:51,55 vs lib/meter.ts:55-57).

**Quote.** `quoteOf(units, terms)` and `verdictOf(q, ctx)` are pure (lib/quote.ts:116-150, 206-280; `Unit.count` multiplies before rounding :123-124; gate order approval→allowance→cap→held, held is `allow:true` :264-272; `QUOTE_TTL_MS` 120 s :292, `isStale` has no callers). Callers: only lib/impact.ts:97,103,334 (Rig). **The composer never calls it** — it prices from the browser rate table (components/make/Composer.tsx:161-168, lib/rateTable.ts:111-142) and /api/generate gates with `estimateCostUsd` + `allowanceCheck`/`checkCap`/`checkLimits` directly (app/api/generate/route.ts:815-834).

**What the SOW §1.1 wants that is absent:** `workspace.internal → 1.0×` (only `internal_test` exists, consumers app/api/admin/previews/route.ts:67 and UI badges; `marginFor` takes no workspace); per-engine multiplier in a registry; `concurrency_samples` per minute (peak is derived on read from meter spans for 30 days, lib/meter.ts:160-174, lib/concurrency.ts:60-95, admin only); nightly floor guard and admin alert (vercel.json:7-12 declares one cron, `/api/cron/sync` every 10 min, no margin logic); a debit row and atomic check-then-meter (lib/credits.ts:57 and lib/meter.ts:64 are separate statements, by design never refuse); `multiplier_applied` on the row; `billed_credits` is REAL, integrality is JS-only; adapter-entry-point test (tests/unit/engines.spec.ts:6-35 never calls render/poll and cannot see lib/identities.ts).
