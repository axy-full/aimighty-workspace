# The editing standard: every output editable at the smallest unit

**Draft, 16 Oct 2026. Docs only.** The owner's 15:05 note, section 4 (`docs/redesign-plan.md`): "EDITING IS THE CORNERSTONE (deck first, then every output in the app)". The deck is built first (`docs/plans/deck-editor.md`); this page is the same standard applied to board cards, shots and stills, and a checklist for reviewers of every v25 and v26 PR. No pricing, margins or vendor costs appear here (the repo is public); a price is whatever the server's price path shows on the button.

## The standard (verbatim from the owner)

> - Click any element to edit it (text, image, colour, position, size); a text change never costs a render.
> - Regenerate one thing only (one image, one paragraph, one page visual), never the whole deck.
> - "Change this…" on any selection in plain words, using the mode's engine choice.
> - Version history per page and per element: compare side by side, restore any.
> - Unlimited undo/redo, lock elements, comments, duplicate a page to try an alternative.
>
> Apply the same standard to board cards, shots and stills: every output is editable at the smallest unit.

## Eight rules (what each line means in the product)

1. **Smallest unit.** Every output has a unit a person can point at (below). Pointing selects exactly that unit, not its parent.
2. **A text or layout change costs nothing.** Moving, resizing, recolouring, retyping, reordering never calls an engine and never needs approval. Only an action that calls a paid engine shows a price.
3. **Regenerate one thing only.** The regenerate action acts on the selected unit; its price is for that unit; the rest is untouched, byte for byte. If the engine cannot act on a unit alone, the product says so and offers the nearest unit, with its own price, instead of redoing everything silently.
4. **"Change this…".** On any selection, a plain-words box. In **Agent mode** Atomik picks the engine and shows one all-in price, naming no engine; in **Director mode** the person picks from the offered engines, each with name, strengths, limits and price per unit. The same tool serves the box, Atomik, a saved skill and an outside agent (rule 11), at the same price, through the same approval gate; only a person approves spend (rule 14). The plain words appear in the box before anything is spent.
5. **Versions.** Every change to a unit writes a new version (author, time, reason). Compare any two side by side; restore any (restoring writes a new version; nothing is erased). Versions are per unit, not just per file.
6. **Undo and redo are unlimited** within the session and survive a reload for the unit's history. No confirmation dialogs; undo instead (rule 13).
7. **Lock and comments.** A unit can be locked against edits (and against being regenerated by a plan); comments attach to a unit.
8. **Duplicate to try an alternative.** Any page, card, shot or still can be duplicated; the copy carries the unit's history link, not a shared mutable body.

## The smallest unit, per output type

"Available today" is what the repo shows; anything else is the target and is marked **to build**. An engine path that does not exist today stays "not available" in the product until it is built (no fake buttons).

| Output | Smallest unit | Edit for free | Regenerate one thing | "Change this…" |
|---|---|---|---|---|
| **Deck page** | an element (text box, picture, shape, logo) | retype, move, resize, recolour, crop window, lock | one picture, one paragraph, or one page visual | on a selected element or text range |
| **Text card** (brief, script, treatment page) | a paragraph, a line, a table cell | edit in place (Tiptap), reorder | one paragraph or one scene | on a selected range |
| **Storyboard panel / still** | a panel; within a still, a **region** | crop window, caption, order | the panel; a region (inpaint) where an engine supports it (**to build** per engine) | on a masked region |
| **Character / cast card** | one look, one angle of the sheet | rename, reorder, lock | one angle or one look | on a selected angle |
| **Shot (video take)** | a take; within a take, its **settings** (length, camera, sound) and, where an engine supports it, a **segment or element** (**to build**; the edit engines are not all wired) | trim in the cut, reorder, captions | the take; a fix (at most two per shot in a plan) | on the take or a described change |
| **Cut / timeline** | a clip on the timeline | trim, move, speed, volume, titles, subtitles (Remotion path, no render for text) | one shot's replacement take | on a clip |
| **Voice / sound** | a line or a sound clip | trim, volume, reorder | one line (priced per length) | on a line |
| **Hindi version** | a shot's voice line or lip-synced clip | edit the Hindi text, reorder | one line, then lip-sync of that shot only | on a line |
| **Poster / still on a board** | a text overlay, a picture, a region | move, restyle | the picture or a region | on a selection |

## Cross-cutting requirements
- **Tenant isolation.** Every version, comment, lock and duplicate carries `workspace_id`; no unit's history is visible across a boundary.
- **Cost on the button.** Anything that calls an engine shows `N cr`, `up to N cr` or `free` before it runs and settles as quoted. A failed step that cost nothing says "Nothing billed" and offers Retry under the same approval.
- **Saves itself.** No "save first". An edit is saved as it is made.
- **Plain words.** The words in the UI are the product's vocabulary only; no engine names in Agent mode.
- **Originals untouched.** An edit never changes the uploaded or generated original; it makes a version or a derived rendition (and, for pictures, never auto-crops, squeezes or stretches).
- **Registry first.** Each editing action is a tool in the registry (rule 11), with a mocked test proving an agent can run it, before it gets a button.
- **Readable and sharp.** Rule 15 and `docs/plans/sharpness-5k.md` apply to every edit surface.

## Reviewer checklist (apply to every v25 and v26 PR)

Tick each, or write why it does not apply. A PR that adds an output with a unit but skips an item needs the reason in its body.

1. [ ] The PR names the **smallest unit** of each output it adds or changes, and selecting it selects that unit.
2. [ ] A **text, position, size or colour change makes no engine call** (a test asserts zero calls and zero ledger rows).
3. [ ] **Regenerate acts on one unit only**; a test asserts the other units' bytes and versions are unchanged.
4. [ ] **"Change this…"** exists on the unit, runs the same tool as the button, Atomik and MCP, and shows the plain words before spending.
5. [ ] **Agent mode names no engine** and shows one all-in price; **Director mode** lists engines with name, strengths, limits and unit price.
6. [ ] **Versions:** every edit writes a per-unit version; compare side by side and restore work; restore does not erase.
7. [ ] **Undo and redo** work without confirmation dialogs, across a reload.
8. [ ] **Lock** stops edits and stops a plan regenerating the unit; **comments** attach to the unit; **duplicate** works.
9. [ ] **Originals are byte-identical** (a hash test); no auto-crop, squeeze or stretch.
10. [ ] **Tenant isolation:** versions, comments and locks are scoped by `workspace_id`; a second workspace sees nothing.
11. [ ] **Spend:** the price is on the button; only a person approves; an agent or MCP call is prepared, not approved; failure says "Nothing billed" or the charge.
12. [ ] **Registry:** each action is a tool with a mocked test that an agent can run it.
13. [ ] **Sharpness** items pass in the five-viewport screenshots (`sharpness-5k.md`).
14. [ ] **No engine name, price, margin or vendor cost** leaks into Agent copy or the repo docs.
15. [ ] Anything the engines cannot do at this unit is **marked "to build" or hidden**, not faked.
