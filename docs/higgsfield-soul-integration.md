# Higgsfield Soul integration

Soul Character generation is disabled until an operator explicitly enables it and supplies verified positive prices for both supported sizes. There is no default generation price.

Set these private server environment variables only after verifying the production account's access and quote for `higgsfield-ai/soul/character`:

```dotenv
HF_SOUL_CHARACTER_ENABLED=1
HF_SOUL_CHARACTER_USD_720P=<verified USD for one 720p image>
HF_SOUL_CHARACTER_USD_1080P=<verified USD for one 1080p image>
```

Use the authenticated non-generating estimate endpoint documented by Higgsfield to verify prices. The displayed Soul 2 Standard and Soul Standard prices do not establish a Soul Character price. The application's mock tests use synthetic rates solely to exercise the billing pipeline.

Credentials use the existing workspace vendor-key store under `higgsfield` as `KEY_ID:KEY_SECRET`, or the deployment's private `HF_CREDENTIALS` for workspaces entitled to platform keys. Credentials never enter client code. The binding records a credential fingerprint; a changed connection cannot submit or poll an existing binding until its original connection is restored or its provider outcome is reconciled.

Training acknowledgements also retain their known provider UUID in an independent platform receipt. A missing or unfamiliar status does not discard that UUID. An uncertain submission without a UUID cannot safely be matched by name or by listing account identities; it stays unresolved without another paid POST. Keep the original provider connection available until training and generation settle and any requested remote identity purge finishes.

## Contract and availability

The implementation uses `POST https://api.higgsfield.ai/higgsfield-ai/soul/character`, documented in the [official supplementary OpenAPI](https://docs.higgsfield.ai/docs/openapi.json). It sends the server-resolved `custom_reference_id`, `custom_reference_strength`, the prompt, a supported aspect ratio, `resolution` (`720p` or `1080p`), and `batch_size: 1`. Prompt enhancement is disabled to preserve the application's final prompt. Additional generation reference images are not exposed by this integration.

The current Console's Soul Character model page returned 404 during documentation review on 17 September 2026. [Higgsfield's source-priority guidance](https://docs.higgsfield.ai/docs/llms.txt) identifies model-specific Console documentation as authoritative and OpenAPI as supplementary. The enable flag is an operator assertion that this exact contract is available for the configured account; implementing the adapter does not establish production account access.

**Soul Standard, Soul 2 and Soul Cinema with an identity (28 September 2026).** The model pages for [Soul Standard](https://docs.higgsfield.ai/docs/models/soul-standard/generate.md) (`POST /higgsfield-ai/soul/standard`), [Soul 2](https://docs.higgsfield.ai/docs/models/soul-2/generate.md) (`/higgsfield-ai/soul/v2/standard`) and [Soul Cinema](https://docs.higgsfield.ai/docs/models/soul-cinema/generate.md) (`/higgsfield-ai/soul/cinema`) document `custom_reference_id`, `custom_reference_strength`, `batch_size` 1 or 4, `resolution` 720p or 1080p and seven aspect ratios. Particl models them as `hf-soul-standard`, `hf-soul-2` and `hf-soul-cinema` (`lib/soulRenderTypes.ts`, `lib/soulRender.ts`). An identity renders only with the family it was trained for (`model_version` v1 → Soul Standard, v2 → Soul 2, cinema → Soul Cinema) and only when it was trained on the production host; an identity from the earlier host stays listed, read-only. The request sends the server-resolved `custom_reference_id`, a strength above 0 and at most 1, the batch, size and ratio, and `enhance_prompt: false`; no image references, style or seed. Each request is priced first by the provider's free `POST /estimate/<same path>` with the same body; a reply with no positive number refuses the render, and nothing is sent. The worker prices the same body again just before its single POST and sends nothing if the figure changed. These three models are not behind the Soul Character gate: their price is the live estimate, not a configured rate.

Soul ID training uses the production [custom-reference contract](https://docs.higgsfield.ai/docs/models/soul-id): `POST https://api.higgsfield.ai/v1/custom-references` with the documented `Authorization: Key KEY_ID:KEY_SECRET` header, the name, the signed portrait URLs and `model_version` — `v1`, `v2` or `cinema`, the Soul family the identity is trained for, chosen when it is trained (`v1` when a request names none). The version is stored with the identity. The provider publishes no training price and has no training estimate. v1 trains at Particl's existing fixed training price, unchanged. Soul 2 (`v2`) and Soul Cinema (`cinema`) training cost what the operator sets in private server configuration, converted to credits with the markup like any other API job:

```dotenv
SOUL_TRAINING_USD_V2=<verified USD for one accepted v2 training>
SOUL_TRAINING_USD_CINEMA=<verified USD for one accepted cinema training>
```

Unset (the default) or not a positive number, the family is not offered and a request naming it is refused before anything is written. A training settles at the price it was sent at, even if the setting changes before it finishes.

Every identity carries a versioned host marker (`provider_origin`), stamped with the identity and in its independent platform receipt before the paid request is sent. Status reads, receipt restoration and purge deletes go only to the host named by that marker; the marker is one of two fixed keys and is never taken from input or a provider response. Identities accepted before the marker existed have none and were accepted by the provider's earlier custom-reference host (`dev-api.higgsfield.com`, legacy paired `hf-api-key`/`hf-secret` headers). They keep polling that host, read-only. If a host refuses the status check (401, 403, 404 or 410), the identity shows **Needs review** with an unknown outcome: its reservation stays, it is checked again later, and no training request is ever sent again. A receipt recorded for a different host is never used to restore an identity.

## Studio workflow

**Suites › Studio › Cast on the platform's key (28 September 2026).** *Build identity* trains through `/api/soul/identities` in every workspace: a name, the family it renders with (Soul Standard; Soul 2 and Soul Cinema once priced — only priced versions are shown), 1–40 stills of this project, rights consent, and the training price on the button. The list beneath shows only this workspace's own identities (`soul_identities`), never the provider site's characters. A character renders with a ready identity through `/api/generate/quote` and `/api/generate`: 1 or 4 stills, 720p or 1080p, likeness 100/80/60%, at the live estimate shown as "about N cr" before anything is sent. A batch of 4 is one provider request: the request's take carries its whole price, and its other stills are filed as takes of their own in the same batch strip, at no further charge. A take settles at its quoted estimate (the provider's status reply states no per-job charge; a stated charge would be used only between half and three times the quote). Element builds, the account catalogue's Soul models and its finishing tools are no longer offered in Cast; builds made earlier stay in the Library.

**Cast & Elements is identity-first (four-suites PR F, 19 September 2026).** The product never names the provider: the feature is **Identity** everywhere in the stage, the identity panel and the generation dialog (the settings connection card under Workspace → Engines still names Higgsfield, because an owner connects their own account there). Each cast or element card reads its state from the workspace identity list — *No identity · Identity training · Identity ready · Identity failed* (an `uncertain` training shows as failed until reconciled; a binding the list does not return shows *Identity attached*) — and carries an **Identity** action that opens the panel for that asset. The stage toolbar keeps **Identity** (cast) and **Element identity**. The older LoRA identity trainer (`lib/identities.ts`, `/api/identities`) no longer has an entry point in the Particl suite; its routes, rows and tests stay for accepted trainings, and it remains reachable only from the Library, Rig canvas, Shots and Make asset sheet, marked legacy in code.

A ready identity is the default reference for every take of its character or element: the attached asset carries the identity's original portrait, so any generate node linked to that cast/element node lists it under **Bound references** as `<name> · Identity`. While Soul Character generation stays gated (`HF_SOUL_CHARACTER_ENABLED` unset or unpriced), `/api/workbench/engines` lists no identity engine and the generation dialog says, in one line, that identity rendering is awaiting verification and the take uses the identity's portrait as its reference through the current image engines. Training is unchanged: priced per request through `billCredits`, quoted and admitted exactly as before (`lib/soulIdentities.ts` economics untouched).

Open Cast & Elements, choose **Identity**, and select uploaded or completed generated portraits of one character. Particl accepts 1–40 JPEG, PNG or WebP originals; Higgsfield's API permits up to 100. Several clear views provide better identity coverage than a single image. Soul ID is not a prop, product or environment trainer.

Review the server quote and rights consent, then create the identity. Training remains visible after leaving or reloading. When ready, attach it as a normal character/element asset and add that asset to the canvas. With the verified generation gate enabled, the node's generation dialog offers the identity engine (model `hf-soul-character`, labelled **Identity render**) with an **Identity** selector and likeness strength. Other engines continue to use its original portrait reference. Generation remains gated until a paid qualification confirms the production account's access to `higgsfield-ai/soul/character` and verified 720p and 1080p prices: one owner-approved run in the internal workspace, under a stated spending ceiling (CLAUDE.md rule 1). Only then are the flag and both rates set (top of this document). Completed images enter the existing takes/library and full-resolution download flow.

Workspace owners connect their own account under **Workspace → Engines → Higgsfield**. The platform's legacy workspace uses private deployment environment variables. The new connection form saves the encrypted key pair without returning it. A saved key is configuration, not evidence of successful live training or generation.

The owner-only **Verify connection** action checks the effective workspace connection on the server, including a platform connection held as a Vercel Secret. It uses the documented production custom-reference list GET (`api.higgsfield.ai`, the host new identities are trained on) and, when that response contains a completed identity, the non-generating estimate endpoint for both Soul Character resolutions. It returns only verification categories and quoted USD amounts. It never exposes provider identities or credentials, starts training or generation, changes credits, or enables the model automatically. A skipped estimate is not a successful model-access check; an authenticated list response proves only custom-reference access. Editing an unsaved key clears the previous verification result.

Training is quoted at the linked page's per-request price, translated through existing credit terms. Accepted training requests retain this charge even if training later fails; the UI states this before consent. The separate custom-reference API does not document a training refund policy. A definitive pre-acceptance rejection releases the reservation. An ambiguous submission retains it for reconciliation and never automatically buys another attempt.

## Recovery and billing

Admission resolves a local identity in the requesting tenant, checks that it is complete and bound to the same credentials, and saves its provider UUID and quoted price on the generation. The client supplies only the local identity ID. Soul identity training is for a single face; generic products and locations remain ordinary reusable elements.

The paid submission shares the existing permanent render claim and spend reservation. A POST is never automatically retried after an ambiguous response. Once returned, its request UUID and status URL are retained privately in both the generation and an independent platform receipt before collection. The receipt restores a missing tenant handle after a database outage and is acknowledged only after terminal billing settlement. An unknown submission without a receipt remains pending for operator reconciliation; it is never resubmitted or automatically refunded. Polling accepts only HTTPS status URLs on `api.higgsfield.ai` with the exact matching `/requests/{UUID}/status` path and no redirects. Collection remains available if new submissions are subsequently disabled.

The collector downloads the returned full image, bounds download size, and uses the existing lossless PNG storage path. It settles the saved generation price, not a newly configured rate. Explicit provider failures, moderation rejection, and cancellation settle at zero; network, malformed-result, credential-rotation, and storage failures retain the request and reservation for reconciliation. Neither the provider UUID, connection fingerprint, provider status URL, nor vendor price snapshot is included in the public generation parameters.

See [requests](https://docs.higgsfield.ai/docs/concepts/requests), [authentication](https://docs.higgsfield.ai/docs/authentication), and [retry guidance](https://docs.higgsfield.ai/docs/concepts/errors) for the provider lifecycle.
