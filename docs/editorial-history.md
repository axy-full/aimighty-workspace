# Asset bins and retained cuts

Assets & takes supports up to 50 named bins per private production. An asset can belong to several bins; All assets and Unfiled remain available. The same Organize in bins command appears in the asset’s right-click, touch/keyboard context menu and visible action menu. Creating, renaming and removing bins uses the existing revision-protected draft save and undo history. Removing a bin preserves its media. The server rejects duplicate bin identities/names, duplicate membership and references to missing assets.

Edit & sound → Edit versions retains named cuts separately from the live draft. Each cut freezes shots, frame rate, aspect, audio clips and mix settings, sequence color, source records and reference lineage from an acknowledged saved revision. Version IDs make repeated saves idempotent. The server reads the draft under its write transaction and rejects stale revisions; clients cannot supply an arbitrary snapshot. A lost response is checked against the same saved version identity.

Restoring first saves the current draft and retains a safety version of a non-empty current cut. It then applies only editorial decisions; canvas, script, asset bins and newer source notes remain intact. Missing library entries are restored from retained source records. A conflicting source identity or edits made during the restore request stop restoration. Normal undo remains available. Empty current cuts are already saved before restoration, but do not produce a named safety version.

The first release retains 50 versions per private production, with at most 1 MB of metadata per version. Source bytes are referenced, not duplicated. At the limit, a restore that needs another safety version stops instead of discarding a cut; export history and begin a separate production to continue. Version deletion, cross-production version import and unlimited archival are not implemented. A version download contains the frozen metadata and integrity hash; media bytes remain accessible through their authenticated source URLs. The workspace data export includes the requesting owner’s retained versions and source index. It excludes other collaborators’ private cuts.

Versions and their indexed upload/generation references commit atomically. Retained source identities block ordinary media deletion even after the current draft stops using them. The index avoids scanning full version bodies when checking a deletion. SHA-256 verifies stored metadata on read; this is an integrity check, not a third-party signature. Physical tenant selection, captured request scope, authenticated membership, MFA policy and recovery admissions apply to the API. Complete database backups inventory these tables with the rest of the tenant schema.

Verification covers duplicate/replayed saves, stale revisions, owner and tenant privacy, rollback of source-index failures, concurrent capacity checks, snapshot corruption, bin validation, lineage restoration and source-identity conflicts. Five browser viewports cover persisted bins, named cuts, lost-response recovery, restoration, retained safety cuts and byte-accurate metadata downloads. The browser movie renderer’s three-minute/200 MB limit and the current audio/color processing limits are unchanged.
